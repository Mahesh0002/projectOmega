# OMEGA-PROTOCOL: Sovereign Discovery Engine v2.0
*(The Ascendant Build)*

> **"The search for the solution is not random; it is gravitational. We are not wandering in the dark; we are being pulled towards a global optimum."**

The **OMEGA Protocol** is a high-performance, neuro-symbolic regression and causal inference suite. Moving beyond standard deep learning architectures that approximate patterns within a latent space, OMEGA utilizes an autonomous "Teacher-Student" framework. Its goal? To reverse-engineer the exact, mathematically closed-form physical identities governing chaotic systems from raw, noisy observational data.

## I. Core Philosophy: The Search Dynamics

The discovery process operates on a highly optimized two-phase loop:

- **Divergence Phase (Exploration):** Initial search trajectories must be strictly **orthogonal** (perpendicular in vector space) to maximize coverage of the symbolic search space and avoid local minima.
- **Convergence Phase (Exploitation):** Sub-components and successful residual blocks (discovered via *Protocol Zero*) must merge, utilizing global refinement to resolve all paths toward the singular true physical law.

## II. System Architecture

The engine functions through the asynchronous interaction of three primary logical modules:

### 1. The Explorer (Generative Policy)
A **Transformer Actor-Critic** model that performs rapid, heuristic traversal of the discrete symbolic search space. It operates strictly forward, generating topological skeletons of mathematical equations via **Batched GPU MCTS Rollouts** (running up to 128 parallel agent simulations entirely on VRAM) without natively computing constant values.

### 2. The Alchemist (Continuous Optimizer)
A heavy-compute manager utilizing the **L-BFGS** algorithm with Strong-Wolfe line search. It optimizes the continuous physical constants within the discrete skeletons generated by the Explorer. Mutated branches inherit parameter weights via a **Cross-Layer Bloodline** to speed up convergence.

### 3. The Shadow (Intervention Manager)
A parallel surveillance node. If the primary exploration path stagnates (validation loss plateaus for $> 8$ generations), the Shadow node injects neuro-mutations (structural diversity) to force the system out of local minima.

## III. Engine Constraints & Advanced Mechanics

Every discovery module within the OMEGA suite is strictly governed by advanced mechanics:

1. **Iron Dome (Zero-Allocation Physics Kernel):** The computational graph must not break. Singularities (e.g., division by zero) are managed via soft-guard epsilon routing. Furthermore, Iron Dome operates on a static, zero-allocation buffer, entirely preventing Python Garbage Collection choking during millions of MCTS rollouts.
2. **Causal Perturbation Module:** OMEGA doesn't just curve-fit. It computes the Causal Jacobian of candidate equations against the input matrix, aggressively penalizing non-causal variables and ensuring true physical relationships.
3. **Protocol Zero (Iterative Residual Fitting):** Also known as "Onion Peeling." OMEGA extracts complex multi-term equations one layer at a time, fitting the most dominant signals first, and subtracting the predictions from the target to unmask weaker, chaotic secondary effects.
4. **Pareto Front Conservation:** No generated structure is entirely discarded. Equations are balanced based on **Parsimony** (simplicity) and **Fitness** ($R^2$ accuracy). Failed architectures are sent to an offline graveyard, while elites are maintained in a global pool to cure *Generation Amnesia* during PPO updates.
5. **Path Orthogonality:** Search redundancy is strictly prohibited. If two candidate predictions correlate at $>0.95$, the structurally heavier model is immediately pruned.
6. **The Oracle (O(1) Zobrist Hashing):** To survive the combinatorial explosion of infinite mathematical branches, the MCTS utilizes Incremental Zobrist Hashing. Every explored structural sequence is compressed into a unique 64-bit ID, guaranteeing the engine never wastes compute evaluating the exact same topological graph twice.

## IV. Evaluation Environments (The Benchmarks)

The engine is validated against a gauntlet of specific mathematical and physical failure points:

### Phase 1: Chaotic Dynamics & Oscillators
- **Target:** The Duffing Oscillator (*Built-in to `omega.py`*).
- **Objective:** Reconstruct highly non-linear dynamics ($y = -0.2w_1 - 1.0\theta_1 - 0.5\theta_1^3 + 2.5\cos(\theta_2)$) purely from noisy time-series trajectories, fighting against collinearity and harmonic distortions.

### Phase 2: Asymptotic & Frequency Limits
- **Singularity Benchmark:** Targets $y = 1/(t-2.5)$. The agent must construct algebraic division and survive the vertical asymptote without gradient explosion.
- **The Titan Benchmark:** Targets $y = \tan(t) + \sin(e^t)$. A highly non-linear hybrid forcing the model to resolve both repeating singularities and chaotic frequencies simultaneously.

### Phase 3: Multi-Body Physics
- **Target:** N-Body Orbital Mechanics.
- **Objective:** Infer the Inverse Square Law ($F = G \frac{m_1 m_2}{r^2}$) and isolate secondary planetary perturbations using Protocol Zero.
